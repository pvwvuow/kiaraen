# ۰۹ — راه‌اندازی Supabase از صفر (۵ دقیقه)

این راهنما طوری نوشته شده که حتی اگر اولین بار است Supabase می‌بینی، بدون سردرگمی جلو بروی.
در پایان این مراحل: دیتابیس کامل + احراز هویت + امنیت RLS فعال است و کلیدهای امن اپ را داری.

---

## گام ۱ — ساخت پروژه

1. به [supabase.com](https://supabase.com) برو و با گیت‌هاب ثبت‌نام/ورود کن.
2. **New project** بزن؛ نام: `kiaraen`،Region نزدیک به کاربرانت (مثلاً `Frankfurt`).
3. یک **Database Password** می‌سازد — آن را در یک جای امن (پسوردمنیجر) ذخیره کن.
   ⚠️ این رمز را هرگز در چت، گیتهاب یا ایمیل نفرست. برای ساخت اپ به آن نیاز نداریم؛ فقط برای ورود دستی به دیتابیس.
4. حدود ۲ دقیقه صبر کن تا پروژه Provision شود.

> **پلن Free:** پروژه‌های بدون فعالیت بعد از ~۷ روز متوقف (paused) می‌شوند؛
> از Dashboard دوباره Restore می‌شود و داده نمی‌سوزد. جزئیات: `docs/05-costs-and-limits.md`

## گام ۲ — اجرای اسکیمای دیتابیس (یک‌بار)

1. از منوی چپ: **SQL Editor → New query**
2. کل فایل [`supabase/bootstrap.sql`](../supabase/bootstrap.sql) را باز کن، **همه‌اش** را کپی و در ادیتور Paste کن.
3. **Run** بزن (چند ثانیه). باید «Success» ببینی.

این فایل همین ۵ چیز را می‌سازد (همان مایگریشن‌های نسخه‌دار پوشه `supabase/migrations/`):

| فایل | چه می‌سازد |
|---|---|
| 00001 | جداول محتوای آموزشی (سطح‌ها، دسته‌ها، ۵۰۰۰ واژه، مجموعه‌ها، درس‌ها) — فقط‌خواندنی برای کلاینت |
| 00002 | جداول کاربر (پیشرفت واژه‌ها، لاگ مرور، آزمون‌ها، آمار، پروفایل) |
| 00003 | **RLS کامل** — هر کاربر فقط داده خودش را می‌بیند/تغییر می‌دهد |
| 00004 | تریگرهای آمار (استریک، XP، تعداد یادگرفته‌ها) سمت سرور |
| 00005 | گارد همگام‌سازی (نوشته‌ی قدیمی‌تر از دستگاه دیگر رونویسی نمی‌شود) |

> اگر بعداً اسکیما تغییر کرد، فایل مایگریشن جدید `00006_....sql` بساز — نه bootstrap را دوباره اجرا کن.

## گام ۳ — برداشتن کلیدهای امن (تنها چیزی که اپ لازم دارد)

از منوی چپ: **Project Settings (⚙️) → API**

| در Dashboard | در اپ / CI |
|---|---|
| **Project URL** | `kiara.supabase.url` یا Secret با نام `SUPABASE_URL` |
| **anon / public** یا **publishable** key | `kiara.supabase.anonKey` یا Secret با نام `SUPABASE_ANON_KEY` |

✅ کلید anon «عمومی‌پذیر» است؛ انتشارش به‌خودی‌خود خطرناک نیست چون RLS پشتش است.
🚫 **service_role** هرگز: نه در اپ، نه در ریپو، نه در چت. این کلید از RLS عبور می‌کند.

## گام ۴ — وصل‌کردن کلیدها به اپ

**بیلد لوکال (Android Studio):**
1. `local.properties.example` را به `local.properties` کپی کن (این فایل gitignored است).
2. مقادیر را جای `YOUR-PROJECT-REF` و `YOUR-ANON-PUBLISHABLE-KEY` بگذار.
3. Run بزن — در تب «من» باید «وضعیت سرور: متصل» ببینی.

**بیلد با GitHub Actions:**
1. در ریپو: Settings → Secrets and variables → Actions → **New repository secret**
2. دو Secret بساز: `SUPABASE_URL` و `SUPABASE_ANON_KEY`
3. ورک‌فلوها خودکار این‌ها را به BuildConfig تزریق می‌کنند
   (بدون این Secretها هم بیلد سالم است — اپ در حالت مهمان/آفلاین کار می‌کند).

## گام ۵ — تنظیم احراز هویت ایمیل

از منوی چپ: **Authentication → Providers → Email** → فعال است به‌صورت پیش‌فرض.

- اگر می‌خواهی ثبت‌نام بدون تأیید ایمیل فوری وارد شود: **Confirm email = Off**
- اگر Confirm email روشن بماند (توصیه‌شده برای تولید): کاربر بعد از ثبت‌نام باید ایمیلش را باز کند؛
  در پلن Free، ارسال‌کننده پیش‌فرض Supabase است و سقف ارسال دارد (ساعت ~۲ ایمیل).
  برای تولید واقعی SMTP خودت را در **Auth → SMTP** وصل کن.

**تست سریع:** اپ را باز کن → ثبت‌نام با یک ایمیل واقعی → بعد از «ساخت حساب»، در
Dashboard زیر **Authentication → Users** باید کاربر جدید را ببینی. وارد که شد،
در **Table Editor** جدول `profiles` و بعد از اولین مرور، ردیف‌های `user_word_progress` او ساخته می‌شود.

## گام ۶ — (اختیاری) لود محتوای ۵۰۰۰ واژه به سرور

اپ محتوای باندل‌شده را آفلاین نصب می‌کند؛ آپلود سروری فقط برای به‌روزرسانی از راه دور است:

```bash
pip install supabase
SUPABASE_URL=https://YOUR-PROJECT.supabase.co SUPABASE_SERVICE_KEY=<service_role> \
  python scripts/load_content_supabase.py content-pack.json
```

⚠️ این تنها جایی است که service_role لازم می‌شود — فقط در **ترمینال خودت**، هرگز در CI اپ یا گیت.
